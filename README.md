**03 批量实验管理：研究者预先确认网格或手工组合矩阵，平台依次执行、记录、暂停和恢复剩余任务；执行阶段不调用模型。04 科研数据分析独立汇总实验、导入 CSV、生成图表并核查初稿数字。** 见 [批量实验说明](docs/BATCH_EXPERIMENTS.md)。

当前版本包含混合模型路由、文献元数据、引用推荐、批量实验管理和科研数据分析 Data Agent。工作区入口为 `/workspace`。操作见 [工作区说明](docs/WORKSPACE_OPERATIONS.md)，可靠执行见 [运行说明](docs/RELIABILITY_OPERATIONS.md)，语义质量与交付复验分别见 [评测协议](docs/SEMANTIC_EVALUATION.md) 和 [复验说明](docs/REPRODUCIBILITY.md)。事务幂等、租约、模型调用账本、退避与背压继续保留。

面向 AI 研究生的本地多模态研究规划 Agent。输入一篇或多篇论文 PDF，结合个人研究目标与资源，理解方法和图表、整理实验论证，形成有证据的研究切入点与可证伪的实验方案。

本项目为从零实现的独立工程，不依赖外部工程目录。复用本地缓存中的 Qwen3-VL 与 BGE-M3 权重；增强 API 可选，默认关闭。没有自动模型下载或外部文献搜索。

## 启动

在项目根目录执行：

```powershell
python start.py
```

浏览器访问 **http://127.0.0.1:8010**，API 文档为 `/docs`。默认只监听本机并内嵌一个执行 worker；多个 API 进程需要使用 `--api-only --workers 2` 并另启 `python -m loom.worker_main --supervise`。模型按需加载，不需要同时启动旧项目。

快速演示可安装 `requirements-demo.txt` 后运行 `python start.py --demo`，打开 `/workspace` → **04 科研数据分析** → 加载合成演示数据。此模式使用独立的 `data/demo`，不调用模型、不启动训练；可展示对照表、图表、导出和数字核查。自然语言模型规划需要正常模式。[当前批量实验验收](docs/archive/BATCH_VALIDATION_20260919.md)。

1. 添加论文 PDF，等待页面解析完成，在左侧勾选论文。
2. 输入研究问题，可展开“我的研究背景与资源”补充兴趣、基础、算力和时间。
3. 选择“读懂论文”“探索研究方向”“带证据追问”或“理解图与架构”。
4. 查看执行进度与研究结果。点击引用查看原文区域；在原文预览中可把当前页面带入读图任务。
5. 人工核对结果，可记录判断与备注，导出 Markdown 或包含完整证据、版本和执行信息的 JSON。

研究方向模式输出具体改动、成立假设、实验设置、基线、指标、消融、可行性、否定假设的观察结果，以及需要继续查证的文献搜索式。方案另经过一次模型辅助审查，显示“建议先修改”或“核查后探索”，并给出最先应完成的验证。

## 模型与配置

- 默认模型：本地 **Qwen3-VL-4B-Instruct**，FP16、CUDA、SDPA；单队列串行推理。
- 嵌入：本地 BGE-M3，CPU；BM25 + 稠密召回 + RRF。稠密检索不可用时，事件和结果明确显示 BM25 降级，不生成伪向量。
- 按 ModelScope / Hugging Face 本地缓存查找权重，可用环境变量覆盖路径。

```powershell
$env:LOOM_MODEL_PATH = "C:\path\to\Qwen3-VL-4B-Instruct"
$env:LOOM_EMBEDDING_PATH = "C:\path\to\bge-m3"
$env:LOOM_DATA_DIR = "D:\loom-data"
$env:LOOM_DENSE = "0"  # 可选：只用 BM25，减少 CPU 首次索引时间
python start.py --port 8010
```

不设置上述变量时即可使用当前电脑缓存。离线开关在模型模块与启动入口默认开启。

依赖声明位于 `pyproject.toml`，历史验证版本位于 `docs/environment.json`。迁移完整模型服务时，应先安装匹配 CUDA 的 PyTorch，再安装 `requirements.txt`。本地多模态推理需 Python 3.11+、NVIDIA GPU 和足够内存；CPU 数据演示不要求 NVIDIA GPU。已验证硬件见验证报告。不要盲目升级已可用的 Torch/Transformers 组合。

```text

│   ├── documents.py          # PDF 原生块、坐标、页图、区域渲染
│   ├── model.py              # 本地 Qwen3-VL、串行推理与生成取消
│   ├── retrieval.py          # 混合检索、论文范围过滤和持久化向量

│   ├── engine.py             # 按需读图、研究与实验理解、方向设计
│   ├── verification.py       # 引用摘录匹配、来源类型与未知状态
│   ├── worker.py             # 持久化队列、断点恢复、取消和重试
│   └── export.py             # Markdown 研究记录
├── web/                      # 无 CDN 依赖的中文界面
├── tests/                    # 契约、API、恢复、边界与证据测试
├── scripts/                  # 真实模型验收、界面回归
├── docs/                     # 架构、验证与迁移基线清单
├── evidence/                 # 脱敏后的公开核对材料（回归、真实验证、界面截图）
└── data/                     # 运行数据（不应提交仓库）
```

## Agent 的执行方式

模型先根据论文首页、图注、用户问题与资源，生成受约束的研究路径，选择检索关键词与需要查看的页面。执行器只允许访问所选论文和有效页码，随后完成图文阅读、研究主张提取、实验论证整理，以及可选的研究方案生成。不同模式有不同执行分支。

论文观察与研究启发保存在不同字段。来源摘录进行确定性匹配，随后由同一模型进行一次保守的结论复核；界面明确显示这不是独立验证。模型输出结构不合法时最多修复一次；达到调用预算或生成超时后任务失败并保存已完成阶段，不把失败核验当成通过。新颖性统一标记为未验证。

研究分析是有界 Agent；03 由独立调度器执行已登记的可信训练入口，人工提前确认全部配置和种子，网格遍历不需要模型。每组固定配置，支持联合实验；暂停后继续剩余任务，失败记录保留。旧模型建议与 TPE/API 搜索仅保留历史兼容。04 使用类型化分析计划与确定性计算，生成均值、标准差、差值、约束检查和图表，拒绝不一致口径的直接排名。批量运行的工程能力不等于模型调参有效性。

## 持久化与可靠性

- 上传按 SHA-256 去重，原文只读保存；引用包含文件版本、页码、文本块 bbox。入口使用 1 MiB 阈值临时缓冲，超阈值落盘，再按块交给解析器；这是有界磁盘缓冲，不是端到端直通上传。
- 每页解析与文本证据在同一事务内保存，重试跳过已完成页面。
- 研究阶段完成即保存 checkpoint；独立 worker 按租约接管过期任务，启动不会抢走仍有效的执行权。
- 模型回答单独落盘；已记录回答可以回放，未记录回答保留未知状态。
- SSE 按 run_id 保存事件，支持 Last-Event-ID 断线续读；不存在全局回调覆盖。
- 本地队列最多 12 个活动任务；队列满返回 429，UI 显示原因。
- GPU 生成串行执行；取消和生成截止在 token 边界检查，模型加载和单次预填充无法瞬时中断。
- 每次任务保存模型用量、检索方式、证据快照、Prompt 版本；人工复核追加存储，不覆盖原始生成。
- 累计模型调用预算不会因人工重试重置；暂时错误的退避时点、恢复上限与绝对任务期限持久保存。
- 每个阅读阶段从检索结果中选取相关片段；输入上限为 5500 token，默认阅读证据约 6800 字符。生成只计算末尾 token 的 logits，以控制长文本预填充显存。
- 工作流 Prompt 版本改变时，不混用旧任务的阶段结果；旧记录保留，新建研究使用新版本。

## 证据标签的准确含义

| 标签 | 含义 |
|---|---|
| 摘录匹配 | 引用 ID 属于本任务，摘录在给定文本中存在；不意味着语义已被独立核实 |
| 引用待复核 | 引用缺失、ID 不存在或摘录不匹配 |
| 视觉解读 | Qwen3-VL 对页图/区域的理解，必须对照原图核实 |
| 模型推断 | 作者没有直接说出的解释或推理 |
| 研究假设 | 供进一步验证的切入点，不代表已有创新性或一定有效 |

没有从当前检索片段找到某个实验，不等于论文没有做。只输入本地论文，也无法证明某个方向从未被他人研究。系统生成相关工作检索式，供下一阶段核查使用。

## 验证

实验方案以结构化关系记录比较对象、指标、优劣方向、预期关系和实验条件，再生成相互对应的假设与否定条件；JSON 同时保留模型原始草稿。这保证表达关系一致，不保证模型选择的指标方向或科学假设正确。多个指标的方向、取舍与判定规则仍需人工核对。

```powershell
python -m pytest -q
python scripts/smoke_local.py --pdf <论文.pdf> --mode plan
python scripts/check_docs_consistency.py
```

第一条是使用测试替身的故障/契约回归，不加载模型。第二条会调用真实本地模型，以你指定的论文 PDF 运行完整任务，结果写入 `data/evals/`。其耗时受论文长度、首轮向量索引和 GPU 负载影响，不是秒级聊天。

可选 UI 检查使用 Playwright 与已安装的 Microsoft Edge，不下载浏览器：

```powershell
python -m pip install playwright
python scripts/check_ui.py
python scripts/check_result_ui.py
```

检查报告和截图保存在 `data/ui-checks/`。已测范围与未测限制见 `docs/archive/VALIDATION.md`。关键核对材料（全量回归 XML、真实训练数值核对、界面截图与摘要）已脱敏后收录在 `evidence/`；完整记录按[复验说明](docs/REPRODUCIBILITY.md)的分层原则保留在作者本机。

## 后续扩展位置

未来的相关工作检索应作为独立、用户可见的数据源接入：记录检索日期、查询、候选论文及访问限制，再由同一证据层约束结论。先以用户提供的多篇本地 PDF 验证跨论文研究对照；联网服务不应悄悄改变离线承诺。

项目已提供冻结 JSONL、确定性指标和人工复核一致性计算框架；下一步需使用不同 AI 子领域的真实论文完成正式标注，重点建立“主张—方法机制—实验—指标—证据”关系。当前的结构测试、示例评测和单篇本地验收不能代表跨领域质量已达到生产水平，示例数据也不得作为对外指标引用。
