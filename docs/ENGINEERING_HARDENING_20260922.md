# 批量实验与科研数据分析：可靠性补强

## 1. 提交重试不再重复创建批次

03 仍然遵循“预览矩阵 → 确认完整配置 → 创建草稿 → 启动”的流程。浏览器在预览后生成提交标识，保存在当前标签页的 sessionStorage；网络错误后的重试复用这个标识，成功后才清除。再次预览并主动新建批次会生成新标识，允许研究者有意重复实验。

`POST /api/batches` 支持 `Idempotency-Key`（1–200 字符）。同标识、同请求返回原批次；同标识、不同请求返回 409。没有提供标识时，以确认哈希作为兼容去重键；希望同配置另建一批的客户端应提供新标识。

配置、种子、预算等仍由 `confirmation_sha256` 整体绑定。文件校验在写事务外完成，SQLite `BEGIN IMMEDIATE` 内再次检查键并原子写入批次及 `batch_submissions`。并发竞争不会留下重复草稿。已接受请求的重放不重新读取训练工程，即使工程后来移动，也能返回原记录。此处保障的是本地批次创建幂等，不是训练结果严格 exactly-once。

## 2. 启动前检查依赖及资产

03 新增“检查工程依赖与模型资源”按钮；实际启动草稿时自动再检查一次冻结版本。检查包括：

- 已登记源文件存在性、Python 语法和顶层依赖导入。
- `required_modules` 显式声明的包或本地模块，用于补充条件/动态导入。
- 已登记数据集和兼容的 `dataset_files`，以及 `required_assets` 中声明的模型文件。
- 源码、数据、模型资源与创建草稿时的哈希是否一致。

依赖导入在独立 Python 进程中完成，默认 30 秒超时。不执行训练入口；可信依赖的导入本身仍可能有初始化行为，因此它不是安全沙箱，也不能发现所有动态分支缺陷。CPU 演示模式不开放该检查，避免导入训练依赖。

适配器示例（合并到已有本地登记文件中）：

```json
{
  "required_modules": ["torch", "numpy", "pandas"],
  "required_assets": {"encoder_weights": "D:/research-assets/encoder.pt"},
  "evaluation_phase": "training"
}
```

只有确实需要的资产才应登记；示例路径不是随仓库提供的文件。资源缺失不会通过填一个路径得到修复。预检失败时批次保持草稿、不创建训练 Attempt，检查结果进入事件日志。运行时仍再次验证冻结哈希，覆盖检查后文件被修改的情况。

## 3. 训练完成和产物验收分开记录

每个 Attempt 增加 `execution_state`、`artifact_state`、`execution_receipt`。训练入口正常返回后，先生成 `execution-receipt.json`，将配置、manifest、指标、声明产物及存在的进度日志的大小和 SHA-256 写入数据库，记录 `training_completed` 事件，再进行指标及产物验收。

因此“模型已训练完，但 checkpoint 超过验收上限”会显示为训练完成、产物失败，整体 Attempt 仍失败，不能进入成功统计。训练异常、超时和旧版无完成凭据记录，不会仅凭磁盘上有文件就推断为训练成功。

03 中的“训练已完成，但产物验收失败”入口允许研究者选择失败 Attempt，填写至少 10 字的复核依据，必要时调整本次验收的单文件上限。规则如下：

- 批次不能处于运行/正在暂停状态；已取消或耗尽预算的批次保留原状态。
- 校验原完成凭据绑定的全部文件；内容改动、缺失或指标非法都拒绝。
- 可以在 1 字节至 2 GiB 范围内重设验收上限，不修改冻结计划，也不修改原始模型和指标。
- 不启动训练进程、不重新占用 GPU、不产生新的 seed 样本。
- 保存复核理由、旧错误、使用的上限和通过/拒绝结果；成功时重算对应 Trial 的汇总，满足全部完成条件才更新批次状态。

接口：`POST /api/attempts/{id}/revalidate`，请求为 `{"note":"核对原 checkpoint 后调整验收上限", "artifact_max_bytes":268435456}`。上限可省略。复核通过不证明模型科学有效，仅证明原产物符合明确的工程验收条件。旧版失败记录没有完成凭据，不追补成成功。

完成凭据的单文件硬边界为 2 GiB；超过这一边界或缺失文件无法通过本功能救回。上限不是写盘配额，不阻止训练过程中占满磁盘。进程在凭据持久化前崩溃时，结果仍可能未知；平台不通过猜测自动恢复为成功。

## 4. 奖励日志完整性

当前完整训练工程修复了两项奖励日志遗漏：一类分项奖励未累计全部机架；另一类附加奖金在特定条件下未单独记录。标量奖励的计算顺序和公式不变。

每一步检查奖励子项总和与实际返回 reward 一致（相对容差 `1e-10`，绝对容差 `1e-8`）。逐日保留各子项均值及 `mean_step_reward`，二者也可以独立核对；子项均值不能直接与一天的 reward 总和比较。历史日志不回填，不拿新字段伪装旧版已完整记录。

隔离回归包含 501 组状态，涵盖多个奖励分支与边界条件；新旧函数的标量 reward 逐例相等，分解合计最大误差约 `2.14e-14`。这属于日志正确性证据，不代表策略效果改善。

## 5. 04 参数筛选和逐日分析

04 保持独立的数据分析功能，不重新成为自动调参控制器。新增“最终指标 / 逐日指标”维度选择、参数筛选、天数范围、曲线及 CSV 导出。

参数筛选为确定性 DSL：同一参数的多个值取并集，不同参数的条件取交集。例如固定 `thermal_penalty_weight=1`，选择两个迁移惩罚系数，只对选中的实验组做分析。不存在的参数、空筛选结果、重复条件、非有限值均拒绝；失败记录也保留参数，支持筛选后检查失败分布。CSV 导入目前没有参数列，因此不能凭空推断参数。

逐日数据必须由适配器显式登记 `timeseries_artifact`、`timeseries_axis`、`timeseries_metadata`，对应文件也必须列入 `artifact_files`。平台校验已验收产物哈希；有完成凭据时再核对数据库绑定的文件信息。只有唯一的正整数天数、有限数值、已声明字段才能进入快照。当前单个逐日文件最多 10 MiB/10000 天，单次快照最多 20000 条逐日指标记录，过大时提示缩小批次范围。

```json
{
  "operation": "trajectory",
  "metrics": ["grid_energy_kwh", "solar_used_kwh"],
  "filters": [{"parameter":"migration_penalty_weight", "values":[0.5]}],
  "day_start": 2,
  "day_end": 10
}
```

上例提交到 `POST /api/data/datasets/{id}/analyze`，不调用模型。自然语言入口使用同一 DSL，由模型规划、后端计算；模型上下文包括实际参数、逐日指标和可用天数，不能返回 SQL 或执行任意代码。界面中已选指标和显式筛选条件优先于模型猜测。

每天分别按 seed 等权计算均值和样本标准差；单 seed 的标准差为空。同日、相同种子集合且协议可比时才计算相对基准差值。时间缺口不补零、不插值；不同天数范围应显式选择共同范围，缺失种子不能悄悄丢掉。累计能耗不能冒充每日能耗；奖励权重不同时拒绝合并比较 reward 曲线。物理指标也必须核对代码、数据、模型资产、协议、阶段和单位。

图表、对照表和报告绑定不可变快照，并保留 Attempt、文件名及产物哈希。后续实验完成或人工复核通过后，点击“创建最新快照”生成新数据集；旧数据集和旧报告不随之变化。旧适配器没有显式逐日契约时只支持原有最终指标，不从任意 JSON 猜测字段。

## 6. 升级及验证

数据库升级为增加表/列，旧记录的阶段标记为 `legacy`，不伪造历史完成凭据。服务和独立实验调度器都需要重启后才使用新逻辑；不要在训练进行中强制重启。修改过运行时代码的历史草稿可能无法通过冻结校验，应新建批次，不覆盖 manifest。
