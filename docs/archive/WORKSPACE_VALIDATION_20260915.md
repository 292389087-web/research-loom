## 测试与异常实验

全量自动化测试 **39 项通过，耗时 26.35 秒**；报告：`data/evals/workspace-tests.xml`。原有 24 项测试保留，新增 15 项覆盖路由、引用、训练、分析和数值核查。验证使用临时数据库与明确标记的工程脚本，没有向正式实验库填入假科研结果。测试出现 1 条 Starlette/httpx 弃用警告，无测试失败。

| 故障／场景 | 检查结果 |
|---|---|
| 未许可文献／历史对话／实验计划 | 不能因复杂任务、GPU 忙或强制 API 绕过许可 |
| API 返回 302 | 不跟随跳转，不外发到新地址 |
| API 原始响应重放 | 不产生额外调用；调用预算仍持久有效 |
| 路由检查后 GPU 被抢占 | 调用标为未执行，不消耗模型调用次数 |
| 元数据从旧版本覆盖 | 返回冲突，保留已保存修订 |
| 模型编造 evidence ID | 不进入引用结果 |
| 初稿发生变化 | 原引用位置仍绑定旧版本，不冒充新位置 |
| 重复点击启动 | 不增加 Trial 或重复执行 |
| 同一重复执行启动两个包装器 | CAS 只允许一个进程进入训练 |
| 调度器进程退出 | 训练进程继续持有 GPU 锁，新调度器沿用相同执行身份 |
| 训练进程被终止 | GPU 锁由 OS 回收；结果未知记录失败，不假装成功 |
| 源码在计划冻结后变更 | 训练前拒绝执行，不使用混合版本 |
| NaN／缺失指标 | 不进入成功排名 |
| 训练超时／停止 | 停止执行，保留状态和错误；外部 watchdog 覆盖训练线程失去响应 |
| 普通 0.1 + 0.2 核查 | Decimal 精确处理；单位不一致拒绝核查 |

测试中的优化目标为显式标记的简单函数，只证明执行、采样、汇总和恢复链路，不证明真实训练或任何科研算法效果。

## 显存交接实测

`scripts/validate_gpu_release.py` 进行一次真实短生成，然后释放模型、交还锁，再申请 CUDA 内存。

| 项目 | 实测 |
|---|---|
| 短生成输入／输出 | 28 / 8 token |
| 生成时 PyTorch 峰值 | 8.281 GiB |
| 卸载后仍分配 | 8,519,680 字节，约 8.13 MiB |
| 卸载后仍保留 | 20,971,520 字节，20 MiB |
| 锁交接后 CUDA 分配探针 | 成功 |

首次按“必须为零”断言未通过，因此没有保留该不准确假设。随后增加 CUDA 同步，并记录真实残留；验收阈值明确为 allocated < 32 MiB、reserved < 64 MiB，不把小额残留记成零。

当前 Windows 环境的 `nvidia-smi` 进程显存返回 `N/A`，不能用其证明进程显存归零。PyTorch 分配器不包含全部 CUDA 上下文与其他进程占用；上述探针也不能替代真实训练的容量和吞吐测量。记录：`data/evals/gpu-release-validation.json`。

## 演示时可以展示什么

从业务触发展示架构：一个跨天参数搜索占用 GPU，同时进行论文讨论；资料许可决定能否转 API；实验断电／进程退出可能留下未知状态；重启时要保持输入、模型输出和实验身份一致。

可现场展示：重复启动、取消、杀掉调度器、杀掉训练进程、篡改冻结后的测试代码、返回 NaN、让原生函数阻塞；观察记录、预算、GPU 锁和数据排名的变化。测试脚本应明确标记工程验证，不能把小函数的吞吐或得分包装为真实科研成绩。

API 与本地模型的价值在于资料边界、资源可用性与调用开销。尚未做同一标注集上的“全本地／全 API／混合”质量、延迟、费用对照，因此不能声称混合路由已经提升研究质量或降低了某个百分比的成本。
