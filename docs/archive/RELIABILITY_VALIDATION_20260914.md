## 同机 HTTP 压测

脚本 `scripts/reliability_lab.py` 创建独立数据库、随机本机端口和 **2 个 API 进程**。使用合成论文元数据、16/64 并发的闭环客户端；没有加载 GPU、没有完成研究任务。环境：Windows 11，Python 3.12.7，同机 SQLite WAL。正式记录为 `data/reliability/20260914-001413-81515c/report.json`，包含各源文件 SHA-256。

| 场景 | 请求/并发 | 结果 | 成功响应吞吐 | P95 |
|---|---|---|---|---|
| 元数据查询，持续约 30 秒 | 39,200 / 16 | 全部 HTTP 200 | 1,304.63 QPS | 39.54 ms |
| 元数据查询短批次 | 800 / 64 | 全部 HTTP 200 | 982.61 QPS | 119.90 ms |
| 同幂等键提交 | 64 / 32 | 全部 HTTP 202，仅 1 个 run | 70.89 QPS | 599.60 ms |
| 不同请求，剩余容量 11 | 100 / 32 | 11 个 202、89 个 429，队列最终为 12 | 5.50 个接收/秒 | 1,552.62 ms |

最后一行所有响应约 49.97 QPS，不能把包含 89 次拒绝的数字当作成功接收吞吐。写入场景仍有 SQLite 争用及较高尾延迟，这正是当前单机写事务的限制。

另一次较早版本的 30 秒试跑约 1,633 QPS/P95 25 ms，保留在相邻实验目录。这不是稳定容量保证。最终数字采用上述带代码哈希的记录，不挑最好的一次；30 秒依然不足以代表长期稳态。压测客户端与服务器在同一台机器，存在后台负载和闭环压测的协调遗漏问题；未测跨机网络、多人租户、断网、磁盘故障、开放环到达率、长时间运行或模型任务 QPS。
