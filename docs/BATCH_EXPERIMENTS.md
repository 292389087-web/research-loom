# 03 批量实验管理

2026-09-22 已补充提交幂等、工程依赖预检、训练/产物分阶段验收及 04 的参数和逐日维度，完整契约见 [工程补强说明](ENGINEERING_HARDENING_20260922.md)。升级后需重启服务及实验调度器，新逻辑不会重写历史失败记录。

研究者提前决定候选参数和评价协议，平台负责顺序执行、记录和恢复剩余任务。网格遍历、失败处理和下一项派发均不调用 Qwen、DeepSeek 或其他模型。用户可以在实验结束后自己分析、在 04 查询，或导出记录交给编程工具。节省交互式编程工具额度是使用动机，不承诺具体金额，也不以切换模型会降低智力作为依据。

## 输入与实验矩阵

2026-09-20 表单改进：切换到手工组合时，空编辑框自动生成当前适配器的一组完整 JSON 配置，取上方每项候选的第一个值。可重新生成模板，或检查并格式化 JSON；检查包括数组结构、完整键名、数值候选和重复组合。键名必须对应训练适配器，不能任意新增。模板降低格式错误概率，但手工编辑仍需校验。

“固定评价协议”为必填的说明文字（10–2500 字符），供核对数据版本、训练时长、指标口径及评价阶段；不会改写代码或自动保证所填协议已执行。随机种子至少一个，默认 `11,23,37`；填一个 seed 每组训练一次，填三个每组训练三次。它用于固定随机初始化/采样等随机过程，具体由训练适配器设置，不保证 GPU 运算完全逐位一致。空白 seed 会在页面拦截，不能被转换为 0。

1. 选择已登记的可信训练工程，填写项目、批次名称和评价协议。
2. 参数继续按奖励系数、模型超参数、协议参数分组。每项单值表示固定，多值表示扫描。支持跨组联合实验；联合变化不支持把结果单独归因于某一个参数。
3. 选择网格扫描，平台对候选集做笛卡尔积；或选择手工组合，以 JSON 数组显式提供每一行完整配置，按行顺序执行。
4. 指定共同的随机种子集合、观察指标、可选排序指标、上下限、单次超时、总期限和失败策略。
5. 预览全部配置、变化字段、固定字段、配置数和训练次数，勾选确认后冻结成 draft，再单独启动。

参数仅允许已登记候选值。页面有起点/终点/步长辅助填写，终点在步长对齐时包含；浮点生成值最终仍由后端白名单校验。修改适配器候选集需要在本地更新登记，不允许模型扩展边界。页面不是源码编辑器，也不会修改正在运行的配置。

例如 `MIGRATION_THRESHOLD=[0.50,0.55,0.60,0.65,0.70,0.75,0.80]` 是 7 组；但只有训练入口确实接收并使用该字段、适配器已登记，才可以执行。当前已登记的批次适配器不开放这个字段，其配置注释涉及动作编码语义，不能仅凭变量名断言上述扫描有效。

当前已登记的批次适配器可直接选择 `thermal_penalty_weight=[1,2,3,4]`、`migration_penalty_weight=[0.1,0.2,0.3,0.4]`，其余字段固定，展开为 16 组。3 个 seed 对应 48 次训练。此处只说明候选矩阵，不是已经完成 48 次真实训练。平台沿用该适配器的实际奖励定义，未按示例重新编写奖励公式。

每批最多 100 组，每组最多 10 个不重复 seed。重复候选、重复配置、非有限值、缺失字段、超出登记边界的参数均拒绝。手工组合不能与网格展开混用。学习率、隐藏层配置等可作为已登记超参数；模型权重仍由训练学习，不作为手工枚举字段。

## 确定性与追溯

矩阵按参数名排序后按候选值给定顺序展开；手工组合保留行顺序。冻结的 manifest 保存完整矩阵、矩阵哈希和配置确认哈希，调度器按矩阵索引取值，不调用优化器或模型。修改名称、seed、预算或其他配置后，旧确认哈希不能用于提交。

每个配置建立 Trial，每个 seed 建立独立 Attempt。配置、代码/数据哈希、平台运行时代码哈希、主要依赖版本、stdout、逐步进度、最终指标与产物校验和保留。每次训练使用独立目录和进程。适配器应初始化随机状态并从头训练，不隐式继承上一组模型权重。

2026-09-21 真实训练发现旧版固定 10 MiB 产物上限会拒绝正常的 12,328,092 字节模型 checkpoint。新建计划的适配器支持 `artifact_max_bytes`，默认每个文件 256 MiB，可在本地可信登记中设置 1 字节至 2 GiB；此值随 manifest 冻结。超限错误明确显示实际大小和上限，仍检查文件存在性、路径边界及 SHA-256。旧 manifest 未声明此字段时保持原 10 MiB 规则，不改写历史失败；修改运行时后应新建计划并重启服务/调度进程。该限制是单文件验收上限，并非磁盘总配额，也不会在训练写入过程中强制限额。

系统仍使用本地 SQLite、单调度器 OS 锁和共享 GPU 文件锁。多个 API 进程不代表 GPU 并行训练。关闭浏览器不影响调度；关闭电脑会终止实际训练。电脑休眠期间也不能继续训练，应自行配置系统电源选项。

## 暂停、失败与恢复

| 操作/状态 | 行为 |
|---|---|
| 启动 draft | 开始原始墙钟总期限；串行派发配置及 seed |
| 当前 seed 完成后暂停 | running → pausing → paused；不启动下一 seed |
| 恢复剩余任务 | paused → running；继续已排队及尚未生成的配置，不重复完成项 |
| 某组失败后继续 | 完成该组其他 seed，记录失败并推进下一组 |
| 某组失败后暂停 | 完成该组全部 seed，汇总失败后暂停，人工恢复后继续下一组 |
| 立即取消 | 取消待执行项，由训练监控/调度 watchdog 终止当前包装进程 |
| 训练进程丢失 | 标记失败，说明 outcome unknown，不隐式重跑 |
| 总期限耗尽 | 标记 budget_exhausted；不会悄悄延长预算 |
| 有成功也有失败 | 最终 completed_with_failures，不能宣传全部执行成功 |

暂停不会重置预算；期限包含排队、模型锁等待、加载、数据检查和暂停时间。恢复时原期限已到则拒绝。页面展示“各次超时上限之和”作为预算提醒，不把它当实际耗时预测。

当前没有失败任务自动重训。用户可依据失败记录建立新的手工组合批次。进程创建未能认领任务时保留原有有限启动尝试机制，这不等于对已执行训练自动重试。当前支持的是批次进度恢复，不是模型 checkpoint 续训；后者仍需适配器另行定义优化器、随机状态等完整恢复契约。

源文件/数据发生改变会导致冻结版本校验失败，不会在同一批次悄悄使用新版本。外部未协作进程仍可能占用 GPU；普通训练子进程不是安全沙箱。

## 结果交付与 04

03 提供逐次配置、stdout、进度、逐日记录、失败原因和研究备注，以及 CSV 和完整 JSON 导出。JSON 包含尚未执行的完整矩阵、运行状态、来源 manifest 和事件；大体积模型文件不直接塞入 JSON。

“在 04 分析此批次”创建当时的不可变数据快照。每组带配置编号和参数；成功 seed 可以汇总，失败项独立记录，不按零值计入。奖励权重变化后 reward 不可直接比较；物理指标依旧需要满足代码、数据、协议、阶段、单位和 seed 一致等可比条件。若部分组失败导致 seed 集合不同，应先核查样本完整性。

03 主页面不再生成调参建议。历史建议与决策记录保留，旧接口只为旧单轮流程兼容；批次不能请求模型调参建议。04 自然语言规划仍可按资料许可使用本地或远程模型，与批次执行分离。

## 启动与接口

正常模式在两个终端中运行：

```powershell
cd research-loom
python start.py --port 8010
# 另一个终端，相同目录及 LOOM_DATA_DIR：
python -m loom.lab_worker
```

打开 `http://127.0.0.1:8010/workspace`。只要训练工程已登记，03 无需 API Key 或本地语言模型权重。`python start.py --demo` 仍只允许 CPU 数据分析，不开放真实训练。

| API | 用途 |
|---|---|
| POST `/api/batches/preview` | 验证候选边界、展开矩阵并返回确认哈希 |
| POST `/api/batches` | 提交 spec 和 confirmation_sha256，创建冻结 draft |
| GET `/api/trainers/{id}/preflight` | 独立进程检查已登记依赖、数据及模型资源；启动时再次检查冻结版本 |
| POST `/api/attempts/{id}/revalidate` | 带人工依据复核已完成训练的原始产物，不重训 |
| POST `/api/studies/{id}/start` | 单独启动 |
| POST `/api/studies/{id}/pause` | 当前 seed 完成后暂停 |
| POST `/api/studies/{id}/resume` | 原期限内恢复剩余任务 |
| POST `/api/studies/{id}/cancel` | 立即取消 |
| GET `/api/studies/{id}/export?format=json` | 导出完整记录和矩阵 |

通用框架已有网格搜索功能，本项目不宣称发明搜索算法或编程工具无法实现。可展示的工程价值是预先确认的矩阵、固定来源、无人值守执行、故障后可解释恢复及科研数据交付。验证见 [批量实验验收](archive/BATCH_VALIDATION_20260919.md)。

提交接口接受 `Idempotency-Key`：同键同请求复用批次，不同请求冲突返回 409。04 的“创建最新快照”保留旧数据集；参数筛选按多个条件的交集执行，逐日分析需要新版适配器声明的、哈希已校验的逐日产物。
